2023 — Ноябрь 2024

Система Автоматизации Вентиляции

Проект с открытым исходным кодом, представляющий собой приточно-вытяжную вентиляцию с системой увлажнения, рекуперацией воздуха, тонкой очисткой и регулировкой скорости для квартиры.

  • • Первый этап: Проектирование вентиляции, изучение инженерной части, расчет воздухообмена, сопротивлений воздуховодов, теплопотерь и т.д.
  • • Второй этап: Сборка вентиляции + сборка мебели с интегрированными частями системы, пусконаладочные работы.
  • • Третий этап: Автоматизация. Arduino IDE + ESP8266 + нон-блокинг архитектура + телеграм-интерфейс для контроля и мониторинга системы.
  • • Независимость: Программный комплекс управляет заслонками и собирает данные. Микроконтроллеры можно выключить, выставить заслонки руками, и система продолжит работать независимо от ПО.

Результат: Работа без перебоев 24/7. Аптайм ПО без перезагрузок больше 2000 часов.

C Hell & LLM R&D Phase

Переходный период, изучение С и R&D как сопутствующий ущерб.

C hell: Так как в тот момент я думал об углублении в embedded, решил изучить С. Пару месяцев писал на чистом С: Х-макросы, передача функций через аргументы и т.д. Понял, что мне не хватает ООП, и вернулся к С++ уже с необходимостью в «двух плюсах».

LLM prompt engineering: Писал интерактивные РПГ игры через промпты. Искал способ достичь стабильности игрового мира через разные подходы, разные форматы промптов (текст, JSON, YAML и другое).

Результат: Осознал на собственном опыте фундаментальную проблему LLM — дрифт, галлюцинации, контекстные окна, суммаризация и т.д.

Гипотеза: Разделение игры на две части (С++ бэкенд для данных и LLM для нарратива) — уменьшит фундаментальные проблемы LLM.

Август 2025 — Настоящее время

Game Engine

Текстовая РПГ игра как проверка гипотезы разделения.

  • • Архитектура: Модульная, распределенная, луковичная, микросервисная, DoD.
  • • С++: Классы, шаблоны, RAII, корутины, многопоточность, структуры данных и т.д. Разбирался в чужих библиотеках на С и С++.
  • • Профилирование и логирование: Grafana + Loki + Alloy + Pyroscope. Централизованная система логирования для всех сервисов, собственные метрики для балансировки.
  • • Система обработки ошибок: Первые месяцы писал юнит-тесты и стремился к покрытию в 100%, пока не осознал, насколько это замедляет разработку. В итоге перешел на рантайм-валидацию через ультра-легкий кастомный логгер-обработчик. На данный момент в проекте 1450 рантайм-проверок (1 проверка каждые ~15 строк кода).
  • • Рефакторинг: Подход к обработке ошибок позволил несколько раз делать глобальный рефакторинг, переписывая тысячи строк кода и затрагивая половину модулей проекта даже без компиляции в течение нескольких недель. После чего весь проект собирался за несколько часов. Это невозможно при любом другом подходе.
  • • БД: PostgreSQL, несколько таблиц, десятки встроенных функций, триггеры, индексация и интеграция в игровой движок и Grafana.
  • • DevOps: Докер, CMake, Linux в виртуальной машине (для избавления от тормозов Docker Desktop), настройка окружения и зависимостей.
  • • Структуры данных: Файл сохранения игры занимает около 500 тысяч строк JSON. Выбрал библиотеку для быстрого парсинга таких объемов и переписал данные на DoD архитектуру.

Текущий статус: в разработке, 27к+ строк работающего кода.

Отношение к LLM

Как и все сегодня — я использую LLM почти каждый день, но пока что я не доверяю ей ключевые зоны.

Помощь с синтаксисом, автодополнение, мозговой штурм — в этом LLM нет равных. Так же поиск информации ускорился для меня в разы.

Что касается самого кода — тут моё отношение меняется. Весь С++ код я проверяю и чаще всего переписываю. LLM подсказывает решение проблемы на уровне функции или, может быть, класса. А вот на уровне интеграции нескольких модулей на несколько тысяч строк уже бабка надвое сказала, будет ли это работать.

Те, кто говорят, что LLM сегодня может всё — не пробовали настроить CMake или Docker даже для небольшого размера проекта. Как только проект становится сложнее и нужно настроить ту же Grafana или профилирование - хоть документацию читай, хоть LLM используй, хоть агента подключай — любая, казалось бы, маленькая фича стоит нескольких дней жизни.
